# PR TIMES 管理者画面への不正アクセス（2025年5月）

> 最終確認日: 2026-09-30 ／ 状態: 完了（再発防止策を段階的に実施中、2026年3月まで実装予定）

## 3. 攻撃の流れ（第1報より）

1. **偵察**：4月8〜9日ごろ、攻撃者による偵察と見られる不正アクセスがあった。
2. **認証の突破**：管理者画面への侵入には、IPアドレス認証・BASIC認証・ログインパスワード認証の3つを通過する必要があった。しかし、**コロナ禍でリモートワークに移行した際に許可IPアドレスを増やしており、その中に「追加の経緯が不明なIPアドレス」が存在**していた。攻撃者はこのIPアドレスと、**普段使われていない社内管理の共有アカウント**を使って認証を突破した。
3. **バックドアの設置**：4月24〜25日、管理者画面へ不正アクセスし、不審な操作とバックドアファイルの設置を行った。
4. **残存活動**：4月27〜28日、停止後も残存していたプロセスによる攻撃を確認し、これを特定・停止した。
5. バックドア経由でTelegram通信や海外IPアドレスからの攻撃も確認されており、アクセス権限が別の攻撃者に渡った可能性も指摘されている（報道ベース）。

## 4. 被害・影響

### 4.1 個人情報（最大901,603件）

| 対象 | 件数 |
|---|---|
| 企業ユーザー | 227,023件 |
| メディアユーザー | 28,274件 |
| 個人ユーザー | 313,920件 |
| インポートリスト（メディアリスト等） | 331,619件 |
| 当社スタッフ | 767件 |

### 4.2 発表前の重要情報

- **発表前プレスリリース**：1,182社分、1,682件。決算発表や新商品発表など、**未公表の重要情報**が含まれる可能性がある。株価に影響しうる情報が外部に渡っていた場合、インサイダー取引に悪用されるリスクがある。
- **メディアリスト**：最大20,514件（配信先の記者・メディア関係者の連絡先情報）。

銀行口座・クレジットカード情報は含まれない。

### 4.3 サービスへの影響
プレスリリース配信などのサービス機能自体は、本件による影響を受けず、正常に稼働を続けた。

## 5. 原因

**認証を突破された経緯が「なぜそのIPアドレスが許可リストに入っていたか分からない」という管理不備**にある。コロナ禍のリモートワーク対応という緊急対応の際に加えた設定が、そのまま何年も放置され、追加した経緯の記録も残っていなかった。加えて、その入口には「普段使われていない共有アカウント」という、管理が行き届いていない認証情報が結びついていた。

## 6. 初動対応

- 不審なファイルの検知後、直ちにサービスを停止して調査を開始した。
- 残存するプロセスを特定し、停止した。
- 警察に相談・申告した。
- 顧客への通知を行った。

## 7. 再発防止策

### 7.1 実施済み（2025年5月7日時点）
- 管理者画面のアクセス許可IPアドレスを、**社内接続とVPN接続のみ**に制限
- バックドアファイルが配置された箇所で、不正なファイルを実行できないようにする設定を追加
- 管理者画面にアクセスできる全アカウントのログインパスワードを変更
- 不要な共有アカウントの削除

### 7.2 実施予定（2025年5月7日発表分）
- WAF（Web Application Firewall）の設定見直し（2025年10月末完了予定）
- セキュリティを担保しやすい新管理者画面への移行（2025年12月中旬予定）

### 7.3 追加で決定した措置（2025年6月26日発表）
- **全ユーザー向け二段階認証**（ON/OFF設定可能）：企業ユーザー2025年8月上旬、メディアユーザー同年9月上旬、個人ユーザー同年10月上旬に実装
- **企業ユーザー向けIPアドレス制限**（ON/OFF設定可能）：2025年9月上旬実装
- **パスワードのセキュリティ向上**（文字数・複雑性ルールの強化）：2025年11月下旬実装
- **削除データの保持期間30日間**：誤削除からの復旧を可能にする（2025年12月中旬実装）
- **ログイン通知・ログイン履歴の強化**（場所・デバイス情報の記録、不審なログインの強制ログアウト）：2026年3月下旬実装

段階的な実装スケジュールを明示し、進捗を公表している点が特徴。

## 9. 分析: この事例から学ぶこと

- **「緊急対応の名残」が最大の弱点になる**：コロナ禍のリモートワーク移行という、当時は正当な理由で行った設定変更が、5年近く放置されて侵入口になった。緊急時の一時的な設定変更には、**期限を設けて後で棚卸しする運用**が欠かせない。
- **多要素認証があっても、IPアドレス・BASIC認証だけでは不十分**：3段階の認証があったにもかかわらず突破された。「経緯不明のIPアドレス」という管理漏れ1つで、他の認証層も意味をなさなくなった。認証の「層の数」より「各層の管理の正確さ」が重要であることを示す。
- **共有アカウントのリスク**：「普段使われていない社内共有アカウント」が悪用された。共有アカウントは、誰が使ったか追跡しにくく、パスワード変更や無効化も後回しにされがちである。個人に紐づくアカウントへの統一と、不要な共有アカウントの削除が有効な対策になる。
- **「情報インフラ」としての固有リスク**：プレスリリース配信サービスという業態特有のリスクとして、**未公表の決算情報や新商品情報が漏えいすると、インサイダー取引につながりうる**という論点がある。単なる個人情報保護にとどまらない、金融商品取引法上のリスクも意識する必要がある業種であることを示す事例。
- **透明性の高い進捗管理**：再発防止策を実装時期まで具体的に示し、その後も進捗を公表し続けている点は、他の事例と比べても情報開示の丁寧さで際立っている。
