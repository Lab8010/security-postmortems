# イセトー ランサムウェア攻撃（委託先経由の大規模漏えい、2024年5月）

> 最終確認日: 2026-09-30 ／ 状態: 完了（調査結果・再発防止策を公表済み。個人情報保護委員会が2025年3月に指導）

## 1. 概要

| 項目 | 内容 |
|---|---|
| 企業 | 株式会社イセトー（金融機関・地方公共団体などから通知書の印刷・発送を受託） |
| 顕在化日 | 2024年5月26日（日）、複数のサーバー・PCがランサムウェアで暗号化されていることを確認 |
| 初期侵入 | **VPN機器経由** で基幹系ネットワークに侵入。VPN機器は2021年4月以降アップデートされておらず、脆弱性が未対応だった |
| 権限 | 不正利用された管理者アカウントは **2017年2月から同じパスワード**（英小文字のみ11桁）。**多要素認証は未導入** |
| 攻撃種別 | ランサムウェア（暗号化＋窃取）。窃取データはダークウェブで公開された（2024-06-18） |
| 個人情報 | **3,076,477人**（民間事業者からの委託分 2,509,886人、行政機関等からの委託分 566,561人）。うち要配慮個人情報を含むのは13,150人。ほかにイセトー従業者 441人 |
| 影響範囲 | 影響を受けた委託元は **41団体**（民間32、行政機関等9）。再委託元を含めると **約100団体** |
| 行政対応 | 個人情報保護委員会が **2025年3月19日に指導**（個人情報保護法第147条） |
| 攻撃者 | 公式発表では明示なし。ランサムウェアグループ「8Base」が犯行声明を出したと報じられている（報道ベース） |

## 3. 攻撃の流れ（個人情報保護委員会の公表資料より）

1. **初期侵入**：VPN機器を経由して **基幹系ネットワーク** に侵入した（VPN機器のログ取得の設定が不適切だったため、認証をどう回避したかなど詳細は未確認）。
2. **権限**：基幹系ネットワークの管理者アカウントが不正に使われた。パスワードは推測されやすく、7年間変更されていなかった。
3. **暗号化・窃取**：基幹系ネットワーク上のファイルサーバーとPCから、個人データを暗号化・窃取した。
4. **業務系ネットワークには侵入されていない**。本来、委託元の個人データは業務系ネットワークだけで扱うルールだった。

## 4. 被害・影響

### 4.1 個人情報

- 主に通知書に記載された氏名・住所。送付物によっては次の情報も含まれる。
  - 金融機関の通知書：確定拠出年金、ローン残高などの金額
  - 地方公共団体の納税通知書：税額
  - 健康保険組合のジェネリック差額通知書：要配慮個人情報（医療情報）
- 本人数 3,076,477人（うち要配慮個人情報 13,150人）。

### 4.2 委託元への波及

- 委託元41団体（再委託元を含め約100団体）が、それぞれ自団体の利用者に対して漏えいを公表・通知する必要に迫られた。自治体、銀行、保険会社、健康保険組合などが相次いで公表した。

## 5. 原因（個人情報保護委員会の指摘）

| 安全管理措置 | 問題点 |
|---|---|
| **技術的** | VPN機器を約3年間アップデートせず、認証関連の脆弱性（ブルートフォース攻撃に関するものを含む）が残っていた。管理者パスワードが弱く、7年間変更されていなかった。多要素認証は未導入 |
| **組織的（体制）** | 保管ルールが明文化されていなかった。パスワードポリシーの更新規定が守られていなかった。経営層を含む管理者が状況を把握しておらず、責任分担も不明確だった |
| **組織的（規律に沿った運用）** | 56部署のうち3部署が保管ルールを守らず、個人データを基幹系ネットワークにコピーしていた。**ルールが守られていれば漏えいは起きていなかった**。ログの設定確認も行っていなかった |
| **組織的（見直し）** | 定期的な監査・点検が不十分で、長期間のルール違反を発見・是正できなかった |
| **人的** | 保管ルールが「暗黙のルール」で、従業者が常に確認できる状態ではなかった。効率を優先してリスク回避策が不明確なまま扱う部署があった |

イセトー自身も、作業効率のために **扱ってはならないサーバーに便宜的に保管** し、業務終了後に **削除すべきデータを削除していなかった** ことを原因に挙げている（2024-10-04）。

## 6. 初動対応

- 全社対策本部を設置し、外部専門家の協力で調査した。
- イントラネットと感染が疑われるサーバー・PCを休止し、被害領域を委託元データを扱う領域から切り離して業務を続けた。
- 警察に連絡し、影響する取引先に順次報告・協議した。
- リークサイトを継続的に監視した。

## 7. 再発防止策（2024-10-04 公表）

### 7.1 技術的対策
- 侵入経路になった **VPNを使わない体制** に切り替え、認証を強化して不正アクセスが起きない環境を構築する
- 環境ができるまでは、外部ネットワークとの接続を制限して業務を行う

### 7.2 データの取り扱い
- 受託業務のデータを **管理区域の外へ移せない環境** を構築する
- 業務上必要なデータについて保管期限などのルールを明確に定め、業務終了後に確実に削除する
- ルールが守られているかの **監査を徹底** する

### 7.3 人的対策
- 個人情報を含む情報セキュリティの教育と、ルール遵守の研修を行う

### 7.4 個人情報保護委員会の指導（2025-03-19）
- 指摘された問題点を踏まえて必要かつ適切な措置を講じ、すでに進めている再発防止策を確実に実施・運用し、必要に応じて見直すこと

## 9. 分析: この事例から学ぶこと

- **委託先の事故は、委託元の事故**：41の委託元（約100団体）が影響を受けた。委託元は、委託先の「VPNのパッチ状況」「管理者パスワード」「多要素認証」「データの保管場所と削除」まで確認する必要がある。契約書に保管ルールが書かれていなかった点も、委員会が指摘している。
- **「暗黙のルール」は守られない**：業務系と基幹系を分けるという正しい設計があったのに、明文化されず、監査もされず、3部署が5年ほど違反していた。**設計が正しくても、運用で崩れる**。データを移せない技術的な仕組み（DLP、ネットワーク制御）で担保すべき。
- **データを消さないことがリスクになる**：業務が終わったデータを削除していれば、漏えいはなかった。データの保持期限と自動削除は、最も費用対効果の高い対策の一つ。
- **基本対策の欠如**：3年間パッチを当てていないVPN、7年間変わらない弱いパスワード、多要素認証なし。高度な攻撃ではなく、基本の未実施が原因だった。
- **VPNの廃止という選択**：アサヒと同様、侵入口になったVPNそのものを廃止する対策を選んでいる。
