# IIJ「IIJセキュアMXサービス」への不正アクセス（2025年4月）

> 最終確認日: 2026-09-30 ／ 状態: 完了（2025-07-18に総務省から行政指導）

## 1. 概要

| 項目 | 内容 |
|---|---|
| 企業 | 株式会社インターネットイニシアティブ（IIJ）。「IIJセキュアMXサービス」は法人向けのメールセキュリティ（メールサーバー・セキュリティ機能のアウトソーシング）サービス |
| 侵入時期 | **2024年8月3日以降** にサービス設備が不正アクセスを受けていた |
| 顕在化日 | 2025年4月10日、設備上で不正なプログラムが実行されていたことを確認 |
| 原因 | サービスで利用していた**第三者製ソフトウェア「Active! mail」のゼロデイ脆弱性**（スタックベースのバッファオーバーフロー、JVN#22348866）を悪用された |
| 影響範囲（最大） | 最大 **6,493契約、メールアカウント数 4,072,650件**（IIJセキュアMXサービスの全顧客） |
| 影響範囲（確認済み） | 合計 **586契約**（メールアカウント・パスワード漏えい132契約、メール本文・ヘッダ情報漏えい6契約、連携クラウドサービス認証情報漏えい488契約、重複除外後） |
| 行政対応 | 2025年7月18日、総務省が**通信の秘密の漏えい事案**として文書で指導 |
| 波及 | 同サービスを利用していた日本取引所グループ（JPX）や地方銀行など、多数の組織に影響が及んだ（報道ベース） |

## 3. 攻撃の流れ（第2報より）

1. **侵入**：IIJセキュアMXサービスの設備に、2024年8月3日以降、不正アクセスがあった。
2. **悪用された脆弱性**：サービスで利用していた第三者製ソフトウェア「Active! mail」の **スタックベースのバッファオーバーフローの脆弱性**（JVN#22348866）を悪用された。この脆弱性は、**不正アクセスが発生した時点ではまだ発見されていない、ゼロデイ脆弱性**だった。今回の事案を通じて初めて明らかになった。
3. **発覚と対処**：2025年4月10日に不正なプログラムの実行を確認し、不正アクセスの経路を特定して切り離した。ソフトウェアメーカーの改修を経て、4月18日にJVNで脆弱性情報が公開された。
4. なお、このソフトウェアによるオプション機能は2025年2月に提供終了しており、事案公表時点では既に利用していなかった。

## 4. 被害・影響

### 4.1 漏えいの範囲

| 段階 | 契約数 | メールアカウント数 |
|---|---|---|
| 漏えいのおそれ（第1報） | 最大6,493契約 | 4,072,650件（全顧客） |
| 漏えい事実の確認（第2報） | 586契約（重複除外後） | うちアカウント・パスワード漏えいは311,288件 |

**漏えいした可能性のある情報の種類**
- サービスで作成された電子メールのアカウント・パスワード
- 送受信されたメールの本文・ヘッダ情報
- 連携して動作するよう設定していた他社クラウドサービスの認証情報

不正アクセス発生時点（2024年8月3日）で既に利用を終了していた契約についても、メールアカウントと連携クラウドサービスの認証情報が対象に含まれた。

### 4.2 波及（報道ベース）
IIJセキュアMXサービスを利用していた日本取引所グループ（JPX）や地方銀行など、多数の組織のメールが影響を受けたと報じられている。IIJのサービスという「共通基盤」の脆弱性が、利用企業全体に波及した。

## 5. 原因

**第三者製ソフトウェア「Active! mail」のゼロデイ脆弱性の悪用**。この脆弱性は、攻撃が発生した時点でベンダー・セキュリティコミュニティともに未発見だった。

## 6. 初動対応

- 不正なプログラムの実行を確認後、不正アクセスの経路を特定して切り離した。
- 影響を受けた顧客には、契約状況に応じて個別に案内した。
- 過去に利用していた顧客向けに、専用の相談フォームを設置した。
- 関係機関と連携して対応した。

## 7. 再発防止策（2025-07-18時点で公表）

- サービス設備における**振る舞い検知機能の強化**（2025年6月26日に完了）
- **Webアプリケーションファイアウォール（WAF）の多層化**による防御強化（2025年7月中に完了見込み）
- **社長直轄のプロジェクト**を発足し、サービス全体のセキュリティレベルを高度化

- 損益への影響額

## 9. 分析: この事例から学ぶこと

- **「まだ発見されていない脆弱性」への備え**：KDDI（2026年6月）と同様、ゼロデイ脆弱性が発端だった。ゼロデイは事前に防ぎようがない一方、**振る舞い検知**（異常な挙動を監視する仕組み）の強化が事後の再発防止策として共通して挙げられている。
- **約8か月の潜伏**：2024年8月の侵入から2025年4月の発覚まで、長期間気づかれなかった。さくらインターネット（約3年）ほどではないが、メールサーバーという「常時稼働・常時通信がある」システムほど、異常の検知が難しい可能性がある。
- **共通基盤の脆弱性が多数の組織に波及**：KDDIのISP向けメールと同様、1つのメールセキュリティサービスの脆弱性が、証券取引所や地方銀行を含む多数の顧客組織に影響した。金融インフラに近い組織が、外部のメールセキュリティサービスに依存するリスクを示す事例。
- **通信の秘密という論点**：総務省は「通信の秘密の漏えい事案」として指導した。電気通信事業者が提供するメールサービスは、単なる個人情報保護だけでなく、電気通信事業法上の「通信の秘密」の保護という、KDDIの事例とも共通する規制上の論点を持つ。
