> 最終確認日: 2026-09-30 ／ 状態: 復旧済み。原因は「推測」の段階で公表されており、具体的な再発防止策は公表されていない

## 3. 攻撃の流れ（公式発表の範囲）

1. **初期侵入**：フィッシングなどで従業員のアカウント情報が窃取され、そのアカウントで社内ネットワークに侵入された（推測。経路・方法は不明）。
2. **暗号化**：グループ企業が提供するデータセンター内のプライベートクラウドで、**ドワンゴ専用ファイルサーバーなど相当数の仮想マシン** が暗号化された。
3. **執拗な再攻撃**：発覚後も攻撃が繰り返され、遠隔でシャットダウンしたサーバーを攻撃者が再起動して感染を広げようとした。そのため、ケーブルを物理的に抜いて封鎖した。
4. **情報窃取と公開**：窃取された情報が攻撃者によって公開され、SNS や匿名掲示板で拡散された。

**被害を受けなかった部分**：ニコニコ動画のシステム、投稿された動画データ、映像配信システムは **パブリッククラウド上** で運用していたため被害を受けなかった。

## 4. 被害・影響

### 4.1 業務・事業

| 事業 | 影響 |
|---|---|
| Webサービス | ニコニコのサービス全般が停止し、ニコニコアカウントで外部サービスにログインすることもできなくなった。主要サービスの再開は8月5日、全面的な復旧は9月以降 |
| 出版 | 紙書籍の受注システム、デジタル製造工場、物流システムが停止。新刊は平常水準を維持したが、**既刊の出荷は平常時の3分の1** に落ちた。8月中旬に平常水準へ回復 |
| 経理 | 経理システムと決済システムが停止し、一部の取引先への支払いが遅れた。アナログ対応を含め7月末に平常化 |
| MD（物販） | 運営する複数のオンラインショップで受注できなくなった。認証機能の障害でログインもできなくなった |

- 同じデータセンターを共有していたため、ニコニコを狙った攻撃が **出版・経理など他の事業にも波及** した。

### 4.3 財務（2025年3月期、公式）

| | 影響額 |
|---|---|
| 売上高 | △83億円（うち国内紙書籍 △36.5億円、Webサービス △39.5億円） |
| 営業利益 | △47億円（うち国内紙書籍 △19億円、Webサービス △21億円） |

当期純利益は前期比35.1%減となった。サイバー攻撃の影響がなければ、売上高は約11%増、営業利益は約16%増だったとしている。

## 5. 原因（公式発表から読み取れるもの）

- 社外の大手セキュリティ専門企業の調査によると、経路・方法は不明ながら、**フィッシングなどで従業員のアカウント情報が窃取された** ことが根本原因と推測されている。
- 窃取されたアカウントで社内ネットワークに侵入され、ランサムウェアの実行と個人情報の漏えいにつながった。
- （公式発表から読み取れる構造的な要因）複数の事業が **同じプライベートクラウド／データセンターを共有** していたため、影響がグループ全体に広がった。

## 6. 初動対応

- 被害の拡大を防ぐため、サーバー間の通信を切断し、サーバーをシャットダウンした。攻撃者が遠隔で再起動を試みたため、**電源・通信ケーブルを物理的に抜いた**。
- 社内ネットワークと社内業務システムを停止し、オフィスへの出社を原則禁止にした。
- 各種アカウントをリセットし、社内ネットワーク通信のセキュリティ強化と管理ポリシーの見直しを行った。
- 警察、個人情報保護委員会、関東財務局に報告した。
- **代替手段で事業を継続**：出版はアナログ対応と人手の増強で新刊の供給を維持した。ニコニコは開発チームが3日で作った臨時版「ニコニコ動画（Re:仮）」を公開した。
- **二次被害の抑止**：漏えい情報の拡散者に対し、削除要請、発信者情報開示請求、刑事告訴を行った（悪質と認識した書き込みはドワンゴ関連で896件、学園関連で67件）。

## 7. 再発防止策

**具体的な技術対策は公表されていない**（2026-09-30時点）。公表されているのは次の範囲にとどまる。

- 社外の大手セキュリティ専門企業の助言とチェックを受けながら、さらに対策を講じる（2024-08-05）
- 各種アカウントのリセット、社内ネットワーク通信のセキュリティ強化、管理ポリシーの見直し（ドワンゴ、2024-06-14）
- 安全なネットワーク・サーバー環境を構築し直してシステムを再構築した（第2報〜第4報）

**ガバナンス面**（統合報告書2025）
- 監査委員会が **情報セキュリティ体制を重点監査の対象** とし、システム障害への対応について監査した。

## 9. 分析: この事例から学ぶこと

- **「アカウント1つ」で全体に広がる**：窃取された従業員アカウントから、データセンター全体の仮想基盤にまで被害が広がった。認証情報が盗まれる前提で、多要素認証、特権アカウントの分離、仮想基盤の管理画面へのアクセス制限を設けておく必要がある。
- **共有基盤は「巻き添え」を生む**：ニコニコを狙った攻撃が、同じ基盤を使う出版・経理にも及んだ。事業やシステムの重要度ごとに基盤・ネットワーク・管理者権限を分けておくと、被害を局所化できる。
- **パブリッククラウドの部分は無事だった**：動画データと配信システムは被害を免れた。オンプレミス・プライベートクラウドとクラウドを混在させる場合は、それぞれの防御と復旧手順を別々に設計する。
- **攻撃者は遮断に抵抗する**：遠隔でシャットダウンしても再起動された。帯域外管理（iLO/IPMI など）や仮想基盤の管理プレーンも侵害されている前提で、物理的に遮断する手順を用意しておく。
- **代替手段が売上を守った**：新刊の供給を維持し、臨時版のサービスを出したことで、影響を抑えた。システムに依存しない最低限の業務手順を平時から用意しておく価値は大きい。
- **漏えい後の「拡散」への対応**：公開された情報がSNSで拡散され、二次被害が生じた。削除要請や法的措置の体制を事前に決めておくことも、インシデント対応の一部になる。
- **公表の具体性に差**：侵入経路が「推測」にとどまり、具体的な再発防止策も公表されていない。他社が教訓を得にくいという点で、アスクルの第13報などとは対照的。
