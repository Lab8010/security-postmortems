# さくらインターネット 不正アクセス（2026年8月）

> 最終確認日: 2026-09-30 ／ 状態: 完了（第三報で調査完了・再発防止策を公表、2026-09-10）

## 3. 攻撃の流れ（第三報より）

### 3.1「さくらのレンタルサーバ」
- 一部サーバーへの不正アクセスと、一部サーバーへの **マルウェア設置** を確認。
- 当初（8/17時点）は583アカウントとしていたが、追加調査で368アカウントが加わり、合計 **951アカウント** が対象になった。
- 加えて、2025年7月以降のものとみられる不審な活動の痕跡も確認したが、これは継続的な侵害ではなく、二次被害もないと判断。ただし本件との同一性は客観的に確認できなかった。

### 3.2 販売管理システム
- レンタルサーバーの調査を進める過程で、契約情報などを管理する **別システム（販売管理システム）** への不正アクセスを確認。
- **2023年4月〜2026年3月まで、約3年間にわたって** 発生していたことが判明。
- レンタルサーバーへの不正アクセスとの関連性は、明確な根拠が確認されなかった（別の侵入経路の可能性）。
- 攻撃の具体的な手法（侵入経路、認証方式など）は、模倣攻撃防止の観点から公表を差し控えるとしている。

## 4. 被害・影響

### 4.1 影響を受けた情報（2026-09-10、第三報）

| 対象 | アカウント数 | 情報の内容 |
|---|---|---|
| 「さくらのレンタルサーバ」の一部顧客 | 951 | 利用者識別子、顧客環境に保存された情報（メールデータ、ウェブサイトデータ、ログ情報など） |
| 会員登録している顧客（販売管理システム） | **1,360,563** | 会員ID、会社名、部署名、住所、氏名、電話番号、メールアドレス、生年月日、性別、FAX番号、契約サービス、契約期間、請求金額等 |
| 上記のうち一部 | 30 | ハッシュ化された会員IDのパスワード情報 |

- 販売管理システムには、レンタルサーバーの初期サーバーパスワードと、VPSの管理者初期パスワードも保存されており、影響を受けた可能性があるものは強制的にパスワードを変更した。
- クレジットカード情報は保有しておらず、入力画面の改ざんも確認されていないため、漏えいのおそれはない。

### 4.2 財務
2027年3月期の連結業績への影響は限定的と見込まれ、業績予想の修正は予定していない（2026-09-10時点）。

## 5. 原因

公表されている範囲では、次の2つの事象が確認された。

1. レンタルサーバーのサーバーへの不正アクセスとマルウェア設置。
2. 販売管理システムへの、**2023年4月から2026年3月まで約3年間**にわたる不正アクセス。

**侵入経路、攻撃手法、認証の突破方法などの技術的詳細は、模倣攻撃防止のため公表を差し控えている。** この点は他の多くの事例と異なり、「原因分析」の章そのものが非公開という構成になっている。

## 6. 初動対応

- 不審な通信の遮断、対象環境の隔離、マルウェアの除去、認証情報の見直しなどの封じ込めを実施。
- 自社の専門部門と外部のサイバーセキュリティ専門機関が、サーバー・ログ・設定を対象に、侵入経路・攻撃者の活動・影響範囲を調査した。
- 影響を受けた可能性のある顧客に個別に連絡し、パスワードの変更を案内・実施した。
- 「さくらのレンタルサーバ」を除くサービス提供環境と社内システムについて緊急点検を実施し、他に不正アクセスの兆候がないことを確認した。

## 7. 再発防止策（2026-09-10 公表）

### 7.1 実施済み
- 管理者権限・アクセス権限の総点検と厳格化
- 重要システムへの接続経路の見直しと通信制限の強化
- 認証方式・認証情報の管理方法の見直し
- **EDRの導入範囲の拡大** による監視の強化
- 管理用サーバーのセキュリティ設定の強化

### 7.2 今後実施する施策
- 管理環境・社内システム・サービス提供環境への **多層的なアクセス制御** の強化
- 不正アクセスの早期検知を目的とした、監視対象と検知機能の拡充
- セキュリティログの取得範囲・保管期間・分析体制の見直し
- 「さくらのレンタルサーバ」の **全サーバーの再構築によるクリーンナップ**
- 定期的な外部監査と第三者評価の実施
- 継続的なセキュリティ教育とインシデント対応訓練の強化
- **経営層を含む情報セキュリティガバナンスと報告体制の強化**

## 9. 分析: この事例から学ぶこと

- **約3年間、気づかれなかった不正アクセス**：これまでの掲載事例の中で最も長い潜伏期間。ログの保管期間や監視の粒度が、数年単位の侵害を検知できる設計になっているかを問う事例。「セキュリティに関するログの取得範囲、保管期間および分析体制の見直し」が再発防止策の筆頭に近い位置に置かれているのは、この反省を反映していると考えられる。
- **本番環境と管理システムの分離が、被害の全体像を複雑にした**：レンタルサーバー本体と、契約情報を管理する別システム（販売管理システム）の、2つの異なる侵害が並行して見つかった。両者の関連性を明確にできなかったことは、**システムが分かれていても、認証基盤や監視が統合されていないと、それぞれが独立した侵入口になりうる**ことを示す。
- **「データが持ち出された証拠がない」ことは「安全」を意味しない**：外部持ち出しの明確な証拠がなくても、約136万アカウントの情報が「閲覧または取得された可能性がある」として対応している。証拠不十分（＝長期間のログがない）ことを、楽観的な結論の根拠にしなかった開示姿勢は参考になる。
- **インフラ事業者としての説明責任**：「デジタルインフラサービスを提供し、お客さまの大切な情報をお預かりする事業者として」と、自社の立場を明示して再発防止策を経営課題と位置づけている。
- **技術的詳細を伏せる判断とのバランス**：侵入経路などを「模倣攻撃防止」のため非公表とした点は、アスクル（詳細開示）とは対照的な情報公開方針であり、二次被害防止と説明責任のバランスをどう取るかという論点を提供する。
